**What to do**

- **TCP memory** (alert at {{thresholds.tcpMem}} of `tcp_mem[1]`, or any rise in `TCPMemoryPressures`): see blotcms/blot#2041. On the host, `tail ~/tcpmem.log` shows the trend and `cat /proc/net/sockstat` the sockets. If the count keeps rising with few sockets open, it is leaked accounting: replace or reboot onto a fixed kernel. Stopgap until then: `sudo sysctl -w net.ipv4.tcp_mem="1600000 1800000 2000000"` (lost on reboot).
- **Sample stale** (no new sample for {{thresholds.stale}}): `config/redis/bin/tcpmem-log.sh` stopped running from `/etc/cron.d/blot-redis`, or Redis refused its write (a replica, a write freeze, or `OOM` at maxmemory). Check `systemctl status crond` and `tail ~/tcpmem.log` on the host.
- **Backup stale** (last recorded backup over {{thresholds.backup}} old): `~/backup.log` on the host shows why the hourly `backup.sh` failed or skipped (S3 upload, a drill host, not the active host). **Offsite backup stale** (over {{thresholds.offsite}}): the daily copy to B2 failed: also check the `blot-b2` profile, B2 and `/etc/blot-redis/offsite-bucket`. S3 backups may be fine. **Offsite copy of the storage bucket stale** (over {{thresholds.storageOffsite}}): the daily `blot-storage-offsite` sync to B2 failed or stopped: `~/storage-offsite.log` on the host, the `blot-b2-storage` profile and `/etc/blot/storage-offsite-bucket`. A recorded value that can't be read counts as stale.
- **Host memory low** (available memory under {{thresholds.hostMemory}} of the total for {{thresholds.hostMemoryMinutes}} minutes): this is the machine the check ran on, which is the host Redis runs on. `free -m` and `docker stats --no-stream` show who holds it, and `journalctl -k | grep -i oom` whether the kernel has already killed something. Page cache does not count against it. Restart the unit that has grown, or move to a larger instance.
- **maxmemory** (alert at {{thresholds.maxmemory}}): Redis uses `noeviction`, so writes fail at the limit and the app serves 503s. `tail ~/redis-mem.log` on the host shows the growth. Raise it with `REDIS_MAXMEMORY=<bytes> config/redis/bootstrap.sh <host>` if the instance has the RAM, or move to a larger instance.
- **maxmemory not set**: run `config/redis/bootstrap.sh <host>`, which writes `/etc/redis6/blot-memory.conf` and applies it with `CONFIG SET`.
- **Background save failing**: Redis keeps taking writes (`stop-writes-on-bgsave-error no`), but nothing new reaches disk until a save succeeds. On the host: `df -h /var/lib/redis6`, `sudo tail /var/log/redis6/redis6.log` for the reason, `free -m` and `sysctl vm.overcommit_memory` (should be 1). It clears when a save succeeds.
- **Refused writes** (`OOM`, `MISCONF`, `NOREPLICAS`): see maxmemory and background save above. **Other errors** (alert at {{thresholds.errors}} new errors of one type per 5 minutes): `READONLY` is normal for a moment during a promotion; `WRONGTYPE` or `ERR` in bulk is an app bug. **Rejected connections** mean Redis hit `maxclients`.
- **Restarted or switched host**: expected after a deploy of Redis or a promotion. Otherwise check `journalctl -u redis6` (OOM kill?) and `tail /var/log/redis6/redis6.log` on the host. The host named is from the last 5-minute sample, so right after a promotion it may still be the old one.
- **Slow commands** (alert at {{thresholds.slowlog}} or more): from `SLOWLOG GET` on the host, with the command and its first arguments. One slow command blocks everything else on Redis's single thread. `BGSAVE`/`BGREWRITEAOF` (the time to fork, which every hourly backup causes) are only reported at {{thresholds.fork}} or more: a fork that slow means the dataset or the host needs looking at.
- **Rate limits**: a condition is emailed at most once per {{thresholds.conditionInterval}} (start or clear), and each kind of event at most once per {{thresholds.eventCooldown}} (refused writes: once per hour), with what happened in between merged into the next email.
- Full report without sending email: `NODE_PATH=app node app/scheduler/check-redis-host.js`
