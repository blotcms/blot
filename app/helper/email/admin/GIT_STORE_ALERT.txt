**What to do**

{{#hasMissing}}
- **missing**: a file the newest manifest names is not in the bucket, or a blog on git has no copy at all, so the store has lost data for that blog. Look for what deleted it: `logs green | grep "git-store-served" | grep "<blogID>" | grep -E "op=(sweep|remove|compact)"`. To repair it, either import a full clone of the repository (the owner's, say) into the blog's prefix with `scripts/git/import-repo.js` once its copy is removed, or disconnect and reconnect git for the blog, which starts a new history from the blog folder (the owner then clones again). Check it with `scripts/git/verify-store.js --blog <blogID> --deep` after.
{{/hasMissing}}
{{#hasMismatch}}
- **mismatch**: a file is not the size the manifest says, or a full clone failed index-pack, fsck or making a ref. Look at the blog's last `op=push`, `op=write` and `op=compact` lines, and repair it as for a missing file.
{{/hasMismatch}}
{{#hasSweepErrors}}
- **sweep error**: the store's sweep (which deletes old manifests and packs nothing names) could not run for a blog, often a failed request to the bucket. Nothing is lost; storage only grows until it runs. It runs again tomorrow; look at the blog's `op=sweep` lines if it keeps failing.
{{/hasSweepErrors}}
{{#hasOrphans}}
- **leftover** (orphan): the monthly pass found and deleted a blog's copy under `<blogID>/git/` though the blog is deleted or off git. Removing the blog from git, or deleting it, should already have deleted it, twice, so a removal path missed it: find the blog's last `op=remove` lines (`logs green | grep "git-store-served" | grep "<blogID>" | grep "op=remove"`) and fix the code path that should have run.
{{/hasOrphans}}
{{#hasErrors}}
- **error**: a check, the leftover pass or the scratch cleanup could not run (often a failed request to the bucket). Checks run again tomorrow, the leftover pass next month; check a blog by hand with `docker exec -u 1000 blot-blue node scripts/git/verify-store.js --blog <blogID> --deep`.
{{/hasErrors}}

Every finding is also in the log as `op=verify` (or `op=sweep`, `op=remove`): `logs green | grep "git-store-served" | grep -E "op=(verify|sweep|remove)"` (or `logs blue`, whichever unit ran the job).
