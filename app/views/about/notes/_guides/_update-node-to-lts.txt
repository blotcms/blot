# Update the version of Node

Blot uses the [Node.js LTS](https://nodejs.org/en/about/previous-releases) release named by `NODE_VERSION` in `config/versions.env`. Run the test suite on GitHub against a new Node version before merging an upgrade.

## In the repository

Edit `NODE_VERSION` and `NODE_BASE` (the same version with the image's multi-architecture index digest) in `config/versions.env`. Everything else reads that file: the Dockerfiles take it as build arguments, the GitHub Actions workflows load it with `.github/actions/versions`, and the development and test scripts source it. `scripts/security/check-versions.js` fails if `NODE_BASE` doesn't match `NODE_VERSION` or if a version is repeated elsewhere.

Commit and push to a branch, open a pull request, and wait for GitHub's builds and tests to pass.

## In development

From the repository root with nvm loaded:

```sh
nvm install "$(sed -n 's/^NODE_VERSION=//p' config/versions.env)"
nvm use "$(sed -n 's/^NODE_VERSION=//p' config/versions.env)"
```

These commands read the version from `config/versions.env`. If you use another version manager, select that version. Use the npm bundled with Node.js.

Restart development with `npm start` so Docker Compose rebuilds the app and Agentation images. For dependencies installed directly on the host, run `npm install` under the new Node version to rebuild native modules. The root package does not track a lockfile.

## In production

The app runs in Docker. Merge only after GitHub checks pass, then use the normal app deployment process to publish and deploy the image built with the new Node version.

The iCloud macserver runs directly on macOS and manages its Node version separately. Its runtime, package requirements and PM2 deployment setup are outside this upgrade.
